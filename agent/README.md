# ПК-агент

Шаг 6 плана. Собирает состояние игрового ПК и публикует его в MQTT на Pi
по контракту из п.5.

**Собран и проверен 13.09.2026**: сборка прошла без единого предупреждения,
агент подключился к брокеру на плате и доставил активное окно, температуры
и загрузку процессора. Работает и без прав администратора — но часть
датчиков (загрузка видеокарты) без них молчит.

Про нажатия: обработчик клавиатуры **только увеличивает счётчик** и никогда
не читает, какая клавиша нажата. Содержимое набранного агент не видит.

## Сборка

```bash
winget install Microsoft.DotNet.SDK.8
```

```bash
cd agent && dotnet publish -c Release
```

Получится один самодостаточный `DeskAgent.exe` — рантайм ставить не нужно.

Проще собрать сразу обе программы для ПК одной командой из корня проекта —
они лягут в папку `Программа`, и туда же будет смотреть автозапуск:

```
powershell -ExecutionPolicy Bypass -File pc\build.ps1
```

## Запуск

Окна у агента нет — ни консольного, ни какого-то ещё. Запускает его и
показывает, что с ним, приложение DeskCompanion, на странице «Агент».
Адрес блока агент берёт из настроек приложения, язык журнала — оттуда же.

Где что лежит:

| Что | Где |
|---|---|
| журнал | `%LOCALAPPDATA%\DeskCompanion\agent.log` |
| состояние для приложения | `%LOCALAPPDATA%\DeskCompanion\agent-status.json` |
| адрес блока и язык | `%APPDATA%\DeskCompanion\settings.json` — пишет приложение |

Ключи для отладки из терминала:

```
DeskAgent.exe --console                 # работать и печатать журнал сюда
DeskAgent.exe --host 192.168.1.42       # адрес явно, мимо настроек приложения
DeskAgent.exe --windows                 # как агент видит каждое окно
DeskAgent.exe --list-sensors            # что видит LibreHardwareMonitor
```

Разведку проще смотреть в приложении — там те же две кнопки.

**Права администратора нужны только температурам.** Без них
LibreHardwareMonitor молча отдаёт пустоту, и экран GPU / CPU на блоке будет
пустым (п.6 плана). Всё остальное работает и так. Права агент получает от
задачи планировщика, которую заводит `pc\autostart.ps1`: она поднимает его
с наивысшими правами при входе в систему, без запроса. Запущенный иначе
агент работает без температур — и приложение прямо об этом говорит.

Агент один на сеанс: второй экземпляр, запущенный руками, сразу выходит.
Иначе оба слали бы одни и те же топики, и блок показывал бы то одно, то
другое число нажатий.

## Что публикуется

| Топик | Когда | retain |
|---|---|---|
| `home/pc/active_app` | при смене окна | да |
| `home/pc/activity_1min` | раз в минуту | да |
| `home/pc/audio` | при смене состояния | да |
| `home/pc/media` | при смене трека | да |
| `home/pc/hardware` | раз в 2 секунды | да |
| `home/pc/heartbeat` | раз в 30 секунд | **нет** |

Heartbeat без retain намеренно: сохранённая метка времени после выключения
ПК врала бы, что агент жив, а именно по ней Pi и понимает, что связи нет.

## Почему C#, а не Python

Единственная весомая причина — **LibreHardwareMonitor это .NET-библиотека**.
Здесь она работает внутри процесса; из Python пришлось бы держать запущенным
само приложение LHM и парсить его веб-сервер на `:8085`.

Попутно: один exe без установки рантайма, права через задачу планировщика, и заметно
меньше трений с Defender — связка Python + глобальные хуки + PyInstaller
имеет ровно ту сигнатуру, которую антивирус считает кейлоггером.

## Про приватность

Считаются **только количества** нажатий и кликов, агрегатами за минуту.
Ни один код клавиши не покидает `InputCounter` и никуда не записывается.

Но факт остаётся фактом: агент логирует активное окно и активность всех,
кто садится за этот компьютер, а не только вас. П.6 плана предлагает
принять это как свойство архитектуры — но знать об этом надо.

## Что доделать

- **Точное имя игры**, а не категория «game»: Steam хранит последнюю
  запущенную игру в реестре и локальных логах (бэклог п.12).
- **Пройденное мышью расстояние** — сейчас публикуется ноль. Схема базы
  поле держит, счётчик не написан.
- **Приём команд** с блока: выключение ПК и прочее (бэклог п.12). Топики
  добавляются, архитектура уже готова.
