# Desk Companion

Настольный блок на Raspberry Pi Zero 2 W: часы, погода, качество воздуха,
присутствие за столом и статистика работы за компьютером. Один корпус, один
провод питания. План проекта — [desk-companion-plan.md](desk-companion-plan.md).

Весь интерфейс и вся логика разрабатываются и проверяются **без железа**:
экраны рисуются в браузер, датчики подменяются заглушками, 283 проверки
гоняются на любой машине с Python.

## Железо

| Компонент | Назначение |
|---|---|
| Raspberry Pi Zero 2 W | всё целиком: датчики, экран, брокер, база |
| Экран 4" ST7796S 480×320 SPI с тачем XPT2046 | основной дисплей |
| LD2410 | радар присутствия, видит и неподвижного человека |
| SCD41 | CO2, температура, влажность |
| KY-040 | энкодер с кнопкой |
| Гребёнка 2×20 (PLD-40), провода Dupont, microSD 8+ ГБ | обвязка |

### Распиновка

Номера — физические ножки Pi. Уточнена под ST7796S с тачем; в плане (п.10.5)
она для другого экрана.

| Узел | Сигнал | Pin | GPIO |
|---|---|---|---|
| **Экран** | VCC / GND | **17** / 6 | 3.3 В — см. СБОРКА.md |
| | CS | 24 | GPIO8 (CE0) |
| | RESET | 18 | GPIO24 |
| | DC | 22 | GPIO25 |
| | SDI (MOSI) | 19 | GPIO10 |
| | SCK | 23 | GPIO11 |
| | LED | 12 | GPIO18 (PWM) |
| | SDO (MISO) | 21 | GPIO9 |
| **Тач** | T_CLK / T_DIN / T_DO | 23 / 19 / 21 | общие с экраном |
| | T_CS | 26 | GPIO7 (CE1) |
| **SCD41** | VCC / GND | **1** / 14 | 3.3 В, тройник с энкодером |
| | SDA / SCL | 3 / 5 | GPIO2 / GPIO3 |
| **LD2410** | VCC / GND | 4 / 20 | **5 В**, не 3.3 |
| | TX модуля → RX Pi | 10 | GPIO15 |
| | RX модуля ← TX Pi | 8 | GPIO14 |
| **Энкодер** | + / GND | **1** / 9 | 3.3 В, тройник с датчиком воздуха |
| | CLK / DT / SW | 11 / 13 / 15 | GPIO17 / 27 / 22 |

Линии UART **перекрещиваются**: TX одного идёт в RX другого.

**Четыре тройника придётся спаять.** Ножек 3,3 В у Pi всего две, а нужны они
трём узлам; тач же делит с экраном три линии шины SPI. Два провода Dupont в
одну ножку не втыкаются, поэтому на ножки 1, 19, 21 и 23 идёт по одному
проводу, разветвлённому пайкой. Общая картинка со всеми узлами:
[pi/preview/подключение-всего.png](pi/preview/подключение-всего.png).

## Сборка с нуля

Ниже — короткий маршрут. Подробно, с пайкой гребёнки, прозвонкой и разбором
типовых отказов по каждому узлу — [СБОРКА.md](СБОРКА.md).

### 1. Прошить карту

Raspberry Pi OS Lite через Imager, 32-битную: у Zero 2 W всего 512 МБ, и
64 бита тратят их заметно быстрее без выигрыша на такой плате. В «Edit
Settings» задать hostname, пользователя, SSH и **сеть 2.4 ГГц** — Zero 2 W
пятигигагерцевую не видит.

Про карту: подойдёт любая на 8 ГБ и больше. Класс A1/A2 влияет на
отзывчивость системы и живучесть при круглосуточной записи, но для сборки и
отладки это не принципиально. Для постоянной работы лучше всего карты
«high endurance» — они рассчитаны на непрерывную запись.

### 2. Доставить код и настроить систему

```bash
bash deploy.sh
```

Передаёт `pi/` на плату через tar по ssh, без баз, кешей и превью — около
1 МБ вместо пяти. Адрес можно задать явно: `bash deploy.sh alex@192.168.1.42`.

Дальше на самой плате:

```bash
sudo bash setup-step1.sh && sudo reboot
```

Включает I2C, SPI и UART, отключает Bluetooth (иначе UART достаётся ему, а
на ножках остаётся mini-UART с плавающей скоростью), ставит mosquitto и
sqlite3, создаёт базу и ограничивает журнал systemd — карта расходник.

После перезагрузки — проверка и библиотеки приложения:

```bash
sudo bash check-step1.sh && sudo bash setup-step2.sh
```

Ключевая строка первого — `/dev/serial0 -> ttyAMA0`. Если там `ttyS0`, связь
с радаром будет рваться.

Второй ставит Pillow, numpy, spidev, gpiozero, pyserial, smbus2 и paho-mqtt
**через apt, а не pip**: на Bookworm pip вне venv заблокирован (PEP 668), да
и собирать numpy из исходников на Zero 2 W — часы работы. Добавьте
`--with-ml`, если нужен scikit-learn для Режима 6; он тянет scipy и почти
двести мегабайт, а до накопления 1-2 недель данных всё равно бесполезен.

### 3. Припаять гребёнку и подключать по одному узлу

После каждого узла — проверка. Это главное правило: подключив всё разом,
отказ одного датчика не отличить от ошибки в проводке другого.

```bash
python3 tools/bringup.py kernel
```

```bash
python3 tools/bringup.py display
```

Дальше `touch`, `encoder`, `radar`, `air` — в том же порядке, в каком паяете.
Каждый шаг при отказе печатает, какой провод смотреть.

### 4. Калибровка

```bash
python3 tools/touch_calibrate.py
```

Печатает готовый блок для `[touch]` в `app/config.toml`. Без калибровки тап
уезжает на десятки пикселей.

```bash
python3 tools/ld2410_sniff.py --engineering
```

Показывает энергию по зонам дальности. Покачайте пустое кресло, посидите
неподвижно, выйдите — и подберите пороги по числам, а не на ощупь.

### 5. Автозапуск

```bash
sudo bash systemd/install.sh --backup-to /mnt/backup
```

Поднимает сервис экрана, дашборд и ежедневный бэкап. Проверьте перезагрузкой:
всё должно подняться само.

## Разработка без железа

```bash
cd pi && py preview_server.py
```

`http://localhost:842` — все экраны, кнопки энкодера, ползунки данных. Клик
по картинке идёт через тот же распознаватель жестов, что будет работать с
резистивным тачем: клик — тап, протяжка — свайп.

```bash
py tools/seed.py --days 21 && py dashboard_server.py
```

`http://localhost:843` — дашборд на правдоподобных синтетических данных.

```bash
py -m app.main --fake --lat 55.75 --lon 37.62
```

Сервис целиком: поддельные датчики, настоящая погода, кадры в `preview/live.png`.
На Pi то же самое запускается с `--real` и поднимает железо по конфигу.

### Тесты

```bash
cd pi && py app/test_main.py
```

Файлов шесть, все без железа: `test_gestures`, `test_director`, `test_db`,
`test_main`, `display/test_display`, `drivers/test_drivers`.

## Устройство

```
pi/app/
  main.py        главный цикл: опрашивает источники, рисует, пишет в базу
  director.py    что на экране: карусель, покой или подробности
  hardware.py    единственное место, где живут spidev, gpiozero и pyserial
  state.py       общая структура состояния — источники пишут, экраны читают
  screens/       семь режимов, экраны покоя, настройки, общие виджеты
  sources/       датчики, погода, MQTT, здоровье блока; у каждого свой период
  drivers/       протоколы: LD2410, SCD41, XPT2046, энкодер
  display/       два бэкенда — SPI и PNG — за одним интерфейсом
```

Два принципа, из которых следует остальное:

**Превью гоняет настоящий код отрисовки.** В браузер уходит тот же PNG
480×320, что пойдёт на экран. Если бы страница рисовала интерфейс своими
средствами, получились бы две реализации одного макета — и они разъехались бы
на второй неделе. По той же причине шрифт лежит в репозитории, а не берётся
системный: у Segoe UI и DejaVu разные метрики.

**Транспорт отделён от протокола.** Драйверы знают байты, но не знают про
spidev. Поэтому разбор кадров радара, контрольные суммы датчика воздуха и
антидребезг энкодера проверены тестами до того, как что-либо припаяно.

## Что придётся сверять на живой плате

Написано по документации и проверено логически, но соответствие конкретному
экземпляру не гарантировано:

- **Последовательность инициализации экрана** зависит не только от
  контроллера, но и от платы. Отлаживать интерактивно из REPL.
- **Порядок цветов** — если синий покажется красным, `rotation_bgr = false`.
- **Скорость SPI** — 32 МГц на перемычках 10 см; пойдут помехи, снижайте.
- **Раскладка полей LD2410** — ревизии плат отличаются. Первым делом снять
  сырой поток снифером и сверить.
- **Порог касания** `max_resistance` — подобрать на своей панели.
