# Как устроен интерфейс и как его менять

Коротко: **не картинки, а блоки**. Экран собирается из готовых виджетов,
виджеты берут цвета и размеры из одного файла, а состав и порядок экранов
задаётся конфигом без единой строки кода.

Всё это правится и проверяется **без железа** — нужен только Python.

---

## Три слоя

```
theme.py        цвета, отступы, размеры шрифта, сам шрифт
   ↓
widgets.py      карточка, заголовок, строка карточек, пустое состояние…
   ↓
screens/*.py    экраны: собирают виджеты и решают, что показывать
   ↓
config.toml     какие экраны включены и в каком порядке
```

Чем ниже слой, тем локальнее правка. Отсюда простое правило: **сначала
спроси, на каком слое живёт твоя идея.**

| Хочу | Правлю | Заденет |
|---|---|---|
| другие цвета, отступы, размеры | `app/theme.py` | весь интерфейс разом |
| другую карточку или заголовок | `app/screens/widgets.py` | все экраны, где он есть |
| другой конкретный режим | `app/screens/имя.py` | только его |
| убрать режим или переставить | `app/config.toml` | ничего в коде |
| новый режим | новый файл + строка в конфиге | ничего существующего |

`theme.py` — это то, что в вебе назвали бы токенами дизайна. Там десяток
цветов и четыре размера шрифта, и почти вся внешность проекта следует из
них. Сменить настроение блока — правка одного файла.

## Новый экран

Достаточно класса с методом `render`. Вот работающий пример целиком:

```python
from .. import theme
from ..state import State
from . import widgets as w
from .base import Screen


class SunsetScreen(Screen):
    name = "sunset"        # ключ в конфиге
    title = "Светло ещё"   # видно в заголовке и логах

    def render(self, state, draw, frame):
        width, height = frame.size
        w.header(draw, width, self.title, "до заката", theme.ACCENT, state=state)
        draw.text((width / 2, 150), "3 ч 20 мин",
                  font=theme.font(64, bold=True), fill=theme.FG, anchor="mm")
        for box, (value, caption, color) in zip(
            w.row(width, 200, height - theme.PAD, 3),
            [("07:12", "рассвет", theme.DIM),
             ("18:44", "закат", theme.WARN),
             ("11ч32м", "длина дня", theme.FG)],
        ):
            w.stat_card(draw, box, value, caption, color)
```

Восемнадцать строк, и экран выглядит своим — потому что `header`, `row` и
`stat_card` уже знают про поля, промежутки и скругления. Результат:
[docs/демо-экран.png](docs/демо-экран.png).

Включается строкой в `app/config.toml`:

```toml
[screens]
enabled = [
    "clock.ClockScreen",
    "sunset.SunsetScreen",   # ← вот и всё
]
```

Если экрану нужен ввод — добавьте `handle(action, state)`; вернёте `True`,
и поворот не уйдёт листать карусель. Если нужны подробности по тапу —
заполните `details` и `hit_zones`. Оба необязательны.

## Увидеть результат, не имея устройства

```bash
cd pi && py preview_server.py
```

`http://localhost:842` — все экраны в браузере, с кнопками энкодера и
ползунками данных. **Это не макет**: в браузер уходит тот самый PNG
480×320, который пойдёт на физический экран. Двух реализаций макета в
проекте нет намеренно — они разъехались бы на второй неделе.

```bash
py tools/walk_menu.py --render
```

Кладёт PNG каждого достижимого состояния меню в `preview/меню/` — удобно,
когда правка задевает переходы.

## Что прогнать перед тем, как предлагать правку

```bash
cd pi
py app/test_main.py          # и остальные пять файлов тестов
py tools/check_layout.py     # текст за краем экрана и наезды подписей
py tools/walk_menu.py        # ловушки в меню и неожиданные переходы
```

`check_layout` проверяет каждый экран на трёх состояниях: пусто, длинные
значения, всё сломано. Третье важнее, чем кажется: вёрстку рвут не обычные
данные, а «сильный снегопад с метелью» вместо «ясно» — и приходит это не в
тот день, когда на экран смотрят.

Ни один из инструментов не требует железа.

## Договорённости проекта

**Шрифт лежит в репозитории.** Nunito в `app/Nunito/`, а не системный: у
Segoe UI и DejaVu разные метрики, и вёрстка, выверенная на одной машине,
поехала бы на другой.

**Комментарии объясняют «почему», а не «что».** Строка
`led.value = 1.0` в пояснении не нуждается. А вот почему объекты gpiozero
хранятся полями, а не локальными переменными — нуждается, и эта причина
стоила нам вечера отладки.

**Числа в коде — с обоснованием.** `speed_hz = 32000000` сопровождается
тем, почему не 40. Иначе следующий человек поднимет частоту обратно.

**Экран — витрина, а не пульт.** Режимы не листаются сами по таймеру:
нужный вам экран не должен уезжать, пока вы на него смотрите.

## Устройство остального

```
pi/app/
  main.py        главный цикл: опрашивает источники, рисует, пишет в базу
  director.py    что на экране: карусель, покой, накладки
  state.py       общая структура состояния — источники пишут, экраны читают
  theme.py       цвета, размеры, шрифт
  screens/       экраны и общие виджеты
  sources/       датчики, погода, MQTT, здоровье блока
  drivers/       протоколы: LD2410, SCD41, XPT2046, энкодер
  display/       два бэкенда — SPI и PNG — за одним интерфейсом
  hardware.py    единственное место, где живут spidev, gpiozero и pyserial
```

Экраны **не знают** ни про железо, ни про источники данных: они получают
готовое `State` и рисуют. Поэтому дизайн можно править, ничего не зная про
SPI, а драйверы — не открывая ни одного экрана.
